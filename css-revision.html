02 Session 1 · Fundamentals + Box Model

Review: syntax, selectors, and the cascade

CSS
/* selector { property: value; } */
body {
    background-color: #f5f5f5;
    color: #222;
    font-family: Arial, sans-serif;
}
p { color: #333; }              /* Element */
.card { background: white; }    /* Reusable class */
#header { background: #111827; } /* Unique ID */
h1, h2, h3 { font-weight: 700; } /* Selector list */

For ordinary declarations in the same origin and layer, higher specificity wins; equal specificity uses later source order. IDs outweigh classes, which outweigh element selectors. Inherited text styles fill in when no value is specified on the element. Prefer classes over escalating specificity.

CSS
/* Alternatives: choose one color declaration at a time. */
.example {
    color: red;
    color: #2563eb;
    color: rgb(37, 99, 235);
    color: rgba(37, 99, 235, 0.5); /* 50% alpha */
}
What / Why / Remember
Property / concept What Why Remember
px A CSS pixel, not necessarily a device pixel. Precise borders and small details. Use rem for text that follows the root size.
% A percentage of a property-dependent reference. Fluid width: 80%. Percentage height usually needs a definite parent height.
rem Relative to root font size. Consistent type: font-size: 1rem. Respect user font preferences.
em Relative to font size; font-size uses the parent. Component-relative padding: 2em. Nested font-size values can compound.
vw / vh 1% of viewport width / height. width: 50vw; min-height: 100vh. vw can overflow with scrollbars; modern height units come in Session 6.

See example: the box model

Content → padding → border → margin. Padding sits inside the border; margin sits outside. Background paints through padding; margin is transparent.

HTML
<article class="card">
    <h2>Maya / CSS learner</h2>
    <p>I build clear, responsive interfaces.</p>
</article>
CSS
.card {
    width: 300px;
    max-width: 100%;
    padding: 20px;
    border: 1px solid #ddd;
    margin: 20px auto;
    background: white;
    border-radius: 12px;
    box-sizing: border-box;
}
What / Why / Remember
Property / concept What Why Remember
width / height Preferred box dimensions. Control known dimensions. Avoid fixed heights on variable text.
min-width / max-width Lower / upper width limits. Flexible sizing with boundaries. min-width: 0 lets flex/grid children shrink.
min-height / max-height Lower / upper height limits. Minimum hero space or capped panels. A max-height may need overflow: auto.
padding / border / margin Inner spacing / edge / outer spacing. Separate content and boxes. Vertical margins can collapse in normal block flow.
box-sizing: border-box Includes padding and border in declared width. Predictable sizing. This 300px card has 258px of content; margin remains outside.
overflow / overflow-x / overflow-y Control overflow on both / horizontal / vertical axes. auto creates scrolling when needed. hidden clips; do not hide layout bugs with it.
CSS
.notes {
    min-height: 4rem;
    max-height: 10rem;
    overflow-y: auto;
}
.table-wrapper {
    max-width: 100%;
    overflow-x: auto;
}

Code & practice

  1. Build the profile card from memory.
  2. Change padding from 20px to 30px. Predict the outer width.
  3. Add a long paragraph; try max-height: 120px and overflow: auto.

Common mistakes

  • Padding increases a content-box width.
  • Fixed text heights can clip content at zoom.
  • overflow: hidden can conceal the symptom without fixing the sizing.
Check your work
  • With border-box, the border width stays 300px unless max-width constrains it.
  • With content-box and 20px padding, it would be 342px wide.
  • Text remains reachable in the capped scrolling box.

CSS
.display-demo span {
    width: 150px;
    padding: 8px;
    border: 1px solid #2563eb;
}
.block { display: block; }
.inline { display: inline; }
.inline-block { display: inline-block; }
.none { display: none; }
What / Why / Remember
Property / concept What Why Remember
block / inline / inline-block / none New line / text flow / inline box / no box. Choose participation in normal flow. Ordinary non-replaced inline elements ignore width/height; none also removes accessibility exposure.
position: static Normal flow, the default. Let layout do the work. Offsets do not move it.
position: relative Keeps flow space, can be offset. Anchor an absolute child. Neighbors do not move with the offset.
position: absolute Removed from flow. Place a badge inside a card. Usually anchors to the nearest positioned ancestor.
position: fixed Removed from flow, usually viewport-relative. Keep a help link visible. A transformed ancestor can change the containing block.
position: sticky In flow, then constrained by a scroll threshold. Keep navigation available. Needs an inset, space to move, and a suitable scroll ancestor.
top / right / bottom / left / inset Offsets from containing-block edges. Place positioned boxes. inset: 0 sets all four edges; static boxes ignore offsets.
z-index Stacking level within a stacking context. Layer navigation above content. Large numbers cannot escape an ancestor stacking context; flex/grid items can also use z-index.

Float: its original job

CSS
/* An image inside an article can wrap surrounding text. */
.article-photo {
    float: left;
    width: 100px;
    margin: 0 1rem 0.5rem 0;
}
.article { display: flow-root; } /* Contains the float */

Float is useful for text wrapping. Prefer Flexbox or Grid for page layouts. clear: both moves a following box below floats.

Code & practice

  1. Build the sticky navbar, relative card, absolute badge, and fixed help link.
  2. Remove relative from the card, inspect the badge, then restore it.
  3. Scroll and test at a narrow width.

Common mistakes

  • An absolute child needs the intended containing block.
  • Sticky needs a threshold such as top: 0; ancestor overflow matters.
  • Increasing z-index cannot cross an ancestor stacking context.
  • Do not use display: none on a label meant to remain accessible.
Check your work
  • The badge stays inside the card without covering its heading.
  • Sticky stops at its containing block boundary.
  • The fixed link does not obscure content; add bottom space if necessary.

04 Session 3 · Flexbox + Grid

Part A · Flexbox

Main axis follows flex-direction; cross axis is perpendicular. With row in ordinary horizontal writing, main is horizontal. With column, main is vertical.

HTML
<nav class="navbar" aria-label="Practice navigation">
    <a href="#">Maya</a>
    <div class="nav-links"><a href="#work">Work</a><a href="#about">About</a></div>
</nav>
<section class="cards" id="work" aria-label="Projects">
    <article class="card">Portfolio</article>
    <article class="card">Shop</article>
    <article class="card">Dashboard</article>
</section>
<section id="about"><h2>About</h2><p>I enjoy CSS.</p></section>
CSS
.navbar {
    display: flex;
    justify-content: space-between;
    align-items: center;
    flex-wrap: wrap;
    gap: 20px;
}
.nav-links { display: flex; gap: 20px; flex-wrap: wrap; }
.cards {
    display: flex;
    flex-direction: row;
    flex-wrap: wrap;
    gap: 20px;
}
.card {
    flex: 1 1 250px;
    min-width: 0;
    padding: 20px;
    background: white;
}
What / Why / Remember
Property / concept What Why Remember
display: flex Creates a flex container. Align direct children in one dimension. Container gets alignment properties; children get flex.
flex-direction Sets main-axis direction. Switch a row into a column. justify-content follows the main axis.
justify-content / align-items Main-axis distribution / cross-axis alignment. Center or separate items. Distribution requires free space.
gap / flex-wrap Space between items / allow new lines. Responsive groups without margin hacks. gap does not add outer padding.
flex-grow / flex-shrink / flex-basis Growth / shrink factor / initial main size. flex: 1 1 250px shares space from a 250px basis. Basis is not a minimum width.
order / align-self Visual order / one item’s cross alignment. Adjust an individual item. order does not change reading or keyboard order.

Part B · Grid

Flexbox = mostly one-dimensional layouts. Grid = mostly two-dimensional layouts. Use both: flex for a card’s controls, grid for the collection. Change class="cards" to class="grid" in the HTML:

CSS
.grid {
    display: grid;
    grid-template-columns: repeat(3, 1fr);
    gap: 20px;
}
/* Try instead: fluid columns. */
.grid {
    grid-template-columns: repeat(auto-fit, minmax(250px, 1fr));
}
/* Safer when the container can be narrower than 250px. */
.grid {
    grid-template-columns: repeat(auto-fit, minmax(min(100%, 250px), 1fr));
}
What / Why / Remember
Property / concept What Why Remember
grid-template-columns / grid-template-rows Define column / row tracks. Coordinate two-dimensional layout. Extra content can create implicit rows.
repeat() / fr Repeat tracks / share remaining track space. repeat(3, 1fr) makes three shares. Content minimums may cause overflow; minmax(0, 1fr) permits shrinking.
minmax() / auto-fit Track range / fit and collapse unused tracks. Fluid columns with fewer breakpoints. A fixed minimum wider than the container can overflow.
gap Gutters between tracks. Consistent spacing. Gaps are accounted for before fr distributes space.
grid-column / grid-row Placement by lines or spans. Let featured content span tracks. A two-column span can create an unwanted column on mobile.
grid-template-areas Named rectangular regions. Readable page maps. Each named area must form one rectangle.
HTML
<div class="layout">
    <header class="layout-header">Header</header>
    <aside class="layout-sidebar">Filters</aside>
    <div class="layout-content">Results</div>
</div>
CSS
.layout {
    display: grid;
    gap: 1rem;
    grid-template-columns: minmax(0, 1fr);
    grid-template-areas: "header" "sidebar" "content";
}
.layout-header { grid-area: header; }
.layout-sidebar { grid-area: sidebar; }
.layout-content { grid-area: content; }
@media (min-width: 48rem) {
    .layout {
        grid-template-columns: 12rem minmax(0, 1fr);
        grid-template-rows: auto 1fr;
        grid-template-areas: "header header" "sidebar content";
    }
}
/* Alternate line placement: grid-column: 1 / -1; grid-row: 1; */

Code & practice

  1. Build a Flexbox navbar and Grid card section.
  2. Change flex-direction to column; predict which alignment property moves what.
  3. Compare the fixed grid and auto-fit at 320px, 768px, and 1200px.

Common mistakes

  • justify-content on an item does not align its siblings.
  • Long content may need min-width: 0.
  • Fixed columns need a mobile plan.
  • Visual reordering can disconnect keyboard order from the display.
Check your work
  • Navbar links wrap rather than disappear.
  • Container alignment and item flex rules are on the correct elements.
  • The safe minmax version fits a container narrower than 250px.
  • DOM order remains meaningful with styles removed.

05 Session 4 · Responsive + Typography + Visual Styling

Review: mobile first

Write the smallest useful layout first, then add space and columns when the content needs them. Keep the viewport meta tag from the starter.

CSS
.container { padding: 16px; }
.grid {
    display: grid;
    grid-template-columns: minmax(0, 1fr);
    gap: 20px;
}
@media (min-width: 768px) {
    .container { padding: 32px; }
    .grid { grid-template-columns: repeat(2, minmax(0, 1fr)); }
}
@media (min-width: 1024px) {
    .grid { grid-template-columns: repeat(3, minmax(0, 1fr)); }
}
/* Other common examples, not mandatory device categories: */
@media (min-width: 640px) { /* Only if content needs a change. */ }
@media (min-width: 1280px) { /* Only if content needs a change. */ }

Choose breakpoints by resizing until the layout needs to change. Mobile, tablet, and desktop are useful testing labels, not reliable device detectors.

<section class="container">

    <div class="grid">
        <article class="card"><h2>Portfolio</h2><p>A personal website.</p></article>
        <article class="card"><h2>Library</h2><p>A reading interface.</p></article>
        <article class="card"><h2>Studio</h2><p>A business homepage.</p></article>
    </div>
</section>
CSS
body {
    font-family: Arial, sans-serif;
    font-size: 1rem;
    line-height: 1.6;
}
h1 {
    font-size: 2.5rem;
    font-weight: 700;
    letter-spacing: -0.02em;
    line-height: 1.15;
}
img { max-width: 100%; height: auto; display: block; }
.card {
    padding: 1.5rem;
    background: white;
    border-radius: 12px;
    box-shadow: 0 10px 30px rgba(0, 0, 0, 0.1);
}
.hero {
    padding: 2rem;
    margin-bottom: 2rem;
    color: white;
    background: linear-gradient(135deg, #1e40af, #5b21b6);
}
What / Why / Remember
Property / concept What Why Remember
@media (min-width: …) Styles above a viewport threshold. Enhance the narrow base layout. Place overrides after base styles and test both sides of each breakpoint.
max-width: 100%; height: auto Caps image width and preserves its ratio. Prevent overflow and distortion. HTML width/height reserve space before image loading.
font-family / font-size / line-height Typeface / text size / line spacing. Make paragraphs readable. Unitless line-height inherits well; test enlarged text.
font-weight / letter-spacing Weight / space between letters. Establish hierarchy. Tight tracking suits some headings, not all text.
background / linear-gradient() Paints a surface or generated image. Group sections and add emphasis. Check contrast across the entire gradient.
border-radius / box-shadow Rounded corners / visual shadow. Separate surfaces. Shadows do not alter layout dimensions.

Code & practice

  1. Adapt the card section to mobile, tablet, and desktop.
  2. Add a local image with meaningful alt text and intrinsic dimensions.
  3. Test 320px, 768px, 1200px, and widths near breakpoints.

Common mistakes

  • Desktop fixed widths can force horizontal scrolling.
  • Do not copy popular breakpoints without testing your content.
  • Fixed image heights can distort images unless cropping is intentional.
  • Pale text on a gradient may lack contrast.
Check your work
  • Cards move from one to two to three columns without overlap.
  • Images keep their proportions.
  • At 200% zoom, text and controls remain usable.

06 Session 5 · Selectors + Animations

Review: target precisely

CSS
.parent p { color: #334155; }       /* Any descendant p */
.parent > p { font-weight: 700; }   /* Direct child p */
h2 + p { margin-top: 0; }          /* Next sibling p */
h2 ~ p { line-height: 1.7; }       /* All later sibling p elements */
input[type="email"] { border-color: #2563eb; }
button:hover { background: #1e40af; }
input:focus { outline: 3px solid #1d4ed8; }
li:first-child { font-weight: 700; }
li:last-child { margin-bottom: 0; }
li:nth-child(2) { color: #1e40af; }

Pseudo-class: a state or structural condition, such as :hover. Pseudo-element: a generated or partial element, such as ::after. Generated content should decorate rather than carry essential instructions.

See example: heading, button, and card

HTML
<section class="parent">
    <h2 class="title">Selected work</h2>
    <p>Small interfaces, carefully built.</p>
    <article class="card"><h3>Portfolio</h3><p>Hover over this card.</p></article>
    <button class="button" type="button">Practice button</button>
    <label for="email-demo">Email</label>
    <input id="email-demo" type="email">
    <ul><li>HTML</li><li>CSS</li><li>Accessibility</li></ul>
</section>
CSS
.title { position: relative; padding-bottom: 0.75rem; }
.title::before { content: ""; } /* Empty until given visual styles. */
.title::after {
    content: "";
    position: absolute;
    left: 0;
    bottom: 0;
    width: 3rem;
    height: 3px;
    background: #2563eb;
}
.button {
    padding: 12px 20px;
    border: 0;
    border-radius: 8px;
    background: #1d4ed8;
    color: white;
    cursor: pointer;
    transition: background-color 0.3s ease, transform 0.3s ease;
}
.button:hover { background: #1e40af; transform: translateY(-2px); }
.button:focus-visible { outline: 3px solid #111827; outline-offset: 3px; }
.card {
    padding: 1.5rem;
    background: white;
    transition: transform 0.3s ease;
    animation: fadeIn 0.5s ease;
}
.card:hover { transform: translateY(-5px); }
@keyframes fadeIn {
    from { opacity: 0; transform: translateY(20px); }
    to { opacity: 1; transform: translateY(0); }
}
@media (prefers-reduced-motion: reduce) {
    *, *::before, *::after {
        animation-duration: 0.01ms !important;
        animation-iteration-count: 1 !important;
        transition-duration: 0.01ms !important;
    }
    .button:hover, .card:hover { transform: none; }
}
What / Why / Remember
Property / concept What Why Remember
transition Interpolates a property when its value changes. Smooth interaction feedback. List specific properties; values must change for a transition.
transform Visually moves, scales, or rotates a box. Movement without changing normal-flow space. Neighbors do not move; transforms can create stacking contexts.
animation / @keyframes Runs a named timeline of values. A brief entrance without a hover trigger. Avoid endless decorative motion.
prefers-reduced-motion Queries the user’s motion preference. Reduce non-essential motion. A targeted accessibility override differs from using !important everywhere.
CSS
/* Try separately; later transform declarations replace earlier ones. */
.demo { transform: translateX(10px); }
.demo { transform: translateY(-5px); }
.demo { transform: scale(1.05); }
.demo { transform: rotate(5deg); }
/* Combine functions when both are needed. */
.demo { transform: translateY(-5px) scale(1.05); }

Code & practice

  1. Build the animated button, hover card, and pseudo-element underline.
  2. Reload to see fadeIn. Enable reduced motion in the OS or DevTools and reload.
  3. Predict what each combinator matches before inspecting.

Common mistakes

  • A descendant space and direct-child > mean different things.
  • nth-child counts positions among siblings, not only a matching element type.
  • Pseudo-elements need content and visual styling.
  • Animating width/top repeatedly may cause layout work; prefer transform/opacity where suitable.
  • Hover-only cues do not help keyboard or touch users.
Check your work
  • The underline needs content: "" to generate its box.
  • Keyboard focus is visible without hover.
  • Reduced motion removes movement and makes timing effectively immediate.
  • Only the intended sibling/descendant elements match.

07 Session 6 · Modern CSS + Components

Review: reusable values and fluid sizing

CSS
:root {
    --primary: #1d4ed8;
    --text: #111827;
    --background: #f8fafc;
    --radius: 12px;
}
body { color: var(--text); background: var(--background); }
.shell { width: calc(100% - 40px); max-width: 1100px; margin: auto; }
h1 { font-size: clamp(2rem, 1rem + 4vw, 4rem); }
.full-height {
    min-height: 100vh; /* Fallback */
    min-height: 100dvh;
}
What / Why / Remember
Property / concept What Why Remember
var(--name, fallback) Reads a custom property. Share colors, spacing, and component values. Names are case-sensitive; custom properties inherit and can be scoped.
calc() Arithmetic with compatible values. Subtract fixed gutters from fluid width. Use spaces around + and -.
min() / max() Choose smallest / largest evaluated value. Cap a width or set a lower bound. min(100%, 70rem) fits its parent with a cap.
clamp(min, preferred, max) Bounds a fluid preferred value. Responsive headings with limits. clamp(2rem, 5vw, 4rem) is common; mixing rem into the preferred term helps text scaling. Test zoom.
svh / lvh / dvh Small / large / dynamic viewport height. Handle changing mobile browser controls. svh stays stable with controls visible; lvh uses the large viewport; dvh changes as controls change.
container-type: inline-size / @container Creates / queries a width-query container. Adapt a component to allocated space. The styled card must be a descendant of the queried wrapper.

What / Why / Remember
Property / concept What Why Remember
BEM / reusable classes Predictable naming and shared styles. Change one rule instead of many copies. A modifier supplements its base class; disabled styling needs real disabled semantics.
minmax(0, 1fr) / min-width: 0 Permit tracks and children to shrink. Prevent long content widening the dashboard. Handle text wrapping and table overflow as well.
:focus-visible Matches when the browser determines focus should be indicated. Make keyboard navigation discoverable. Do not globally remove outlines.
@supports Tests support for a declaration. Layer enhancements above a usable fallback. It cannot guarantee an entire component is bug-free.

Professional pass

  • Accessibility: semantic HTML, visible labels, logical DOM order, visible focus, comfortable targets, and readable contrast. Check contrast with a tool; aim for at least 4.5:1 for normal text and 3:1 for large text. Do not communicate meaning through color alone.
  • Motion: respect reduced-motion preferences; essential information must remain available.
  • Compatibility: check features against your target browsers and test there. Keep usable base styles before enhancements.
  • Maintainability: use shallow class selectors, reduce duplication, and avoid unnecessary !important. Fix the cascade instead of escalating it.
  • Performance: remove verified unused CSS after checking all states, optimize images, reserve image dimensions, lazy-load below-the-fold imagery, and limit excess fonts.
  • Rendering: prefer transform/opacity for suitable animation, avoid continuous expensive effects, and measure before adding optimization tricks.
  • Testing: narrow and intermediate widths, content-heavy states, zoom, keyboard, reduced motion, and more than one target browser.

Debug with evidence

Inspect the element → read crossed-out declarations → check Computed values → inspect box dimensions → use Flex/Grid overlays → fix the cause → retest.

CSS
/* TEMPORARY: reveal box boundaries, then remove. */
* { outline: 1px solid red; }

The outline does not alter dimensions but replaces useful focus outlines while active. Remove it after diagnosis; do not ship it.

Code & practice

  1. Refactor repeated card rules into a base class and BEM modifier.
  2. Build the sidebar/content layout and add a long unbroken filename.
  3. Debug an intentionally overridden style, then do a keyboard pass.

Common mistakes

  • Deep selectors make simple overrides difficult.
  • BEM does not require a class on every single element.
  • Removing CSS without checking hover, focus, and error states can break the UI.
  • One successful screenshot is not sufficient verification.
Check your work
  • Shared styles have one source; modifiers express a real variation.
  • The sidebar stacks on narrow screens and long text wraps.
  • All interactive items have visible focus.
  • No temporary outlines or unexplained !important rules remain.

13 Answers

Attempt all questions first. Give yourself one point per substantially correct answer. This is a revision signal, not a certification.

Reveal the separate answer key (1–30)
  1. Content, padding, border, and margin, moving from inside outward.
  2. Padding is inside the border; margin separates the box from surrounding boxes.
  3. Declared width/height includes padding and border, but not margin.
  4. Block starts a new line; inline flows with text and ordinary inline boxes ignore width/height; inline-block flows inline but accepts dimensions.
  5. Relative keeps flow space. Absolute is removed from flow and uses its containing block, commonly a positioned ancestor.
  6. It controls stacking within a stacking context. A child cannot escape its ancestor stacking context by increasing its number.
  7. For primarily one-dimensional alignment such as navigation, toolbar actions, or a row/column of items.
  8. When rows and columns should be coordinated, such as card collections and page regions.
  9. justify-content distributes main-axis space; align-items aligns on the cross axis. flex-direction determines those axes.
  10. Grow factor 1, shrink factor 1, and initial basis 250px. The basis is not a minimum width.
  11. One share of remaining track space. Intrinsic content minimums can affect the final result.
  12. minmax defines a track range. auto-fit fits tracks and collapses unused ones so occupied tracks can expand.
  13. Start with the narrow layout, then enhance with min-width queries where the content needs a change.
  14. rem uses the root font size. em generally uses the element font size; em in font-size uses the parent font size.
  15. Use max-width: 100% and height: auto; intrinsic HTML dimensions reserve its aspect ratio.
  16. A state or structural condition such as :hover, :focus-visible, or :nth-child(2).
  17. It represents generated or partial content. A decorative ::after needs content: "" and visual styles.
  18. A transition interpolates changed values; an animation follows named keyframes and can run without interaction.
  19. It visually moves, scales, or rotates a box without repositioning its neighbors in normal flow.
  20. They centralize reusable values, inherit, and can be overridden within a component or theme.
  21. It keeps a preferred value between a minimum and maximum.
  22. It adapts descendants to an eligible ancestor container; width queries need a size-query container such as container-type: inline-size.
  23. They use small, large, and dynamic viewport heights. dvh can change as browser controls change.
  24. Block, Element, Modifier: card, card__title, card--featured.
  25. They make overrides and maintenance difficult. Fix source order, scope, and selector design first.
  26. Focus tells keyboard users where they are; labels communicate a control’s purpose and its accessible name.
  27. A media feature for the user’s motion preference, used to reduce or remove non-essential motion.
  28. Remove verified unused CSS and duplication, optimize assets, reserve image space, limit excess fonts/effects, and measure bottlenecks.
  29. Computed sizing, box-sizing, padding, min-width, long content, and flex/grid tracks. Fix the cause rather than hiding it.
  30. Structure, links, forms, narrow/medium/wide and intermediate widths, overflow, images, keyboard, contrast, zoom, reduced motion, and target browsers.

24–30: build and repair weak spots. 18–23: repeat missed mini practices later. Below 18: revisit the sessions behind your misses before increasing project complexity.
